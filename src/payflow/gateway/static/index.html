3-Phase Non-Blocking Transaction Architecture

How PayFlow prevents connection pool exhaustion under heavy parallel payment volume.

Phase 1 • Sub-ms OLTP
Claim Idempotency Key
Atomically claims idempotency key in DB and records initial state. Connection immediately returned to pool.
Phase 2 • Zero DB Lock
Downstream PSP Network I/O
Network round-trip to card network / acquirer occurs outside DB transaction, keeping database connection pool available for other requests.
Phase 3 • Sub-ms OLTP
Atomic Terminal Commit
Short atomic commit transitions payment to terminal state, enqueues transactional outbox event, and marks idempotency completed.
